## id vs _id Distinction (CRITICAL)

App uses `book.id` (not `_id`) for all lookups. Pages' `book_id` matches `book.id`. ~1,186 old books have `id !== _id`. Always use `book.id` in queries. Issues: #215, #218.

## Page Count Caches

`pages_count`, `pages_ocr`, `pages_translated` on books are performance caches. Source of truth: `pages` collection. `translation_percent` is never stored — computed at read time. The old `sync-page-counts` cron has been archived; the endpoint now lives at `/api/admin/sync-page-counts` for manual reruns. Counter sync is the responsibility of any worker that writes to `pages` (see pipeline-ops.md "Critical Rules" — Hetzner workers must call counter sync helpers).

## Data Provenance Rule

ALL enrichment must write `field_provenance`: source, method, confidence, date on every metadata write. No silent writes. Issue #362.

**Record the source's claimed VALUE, not just the writing stage.** `field_provenance.<field>` must store *what each source actually returned* (a `claims: [{source, value}]` array), not only `{source:'import', provider:'internet_archive'}`. Otherwise a wrong value wears a trustworthy badge and nothing can detect that the stored value contradicts its own cited source. **When two source signals disagree, surface the conflict** (`<field>_review: true` + record both claims) instead of silently picking one via a precedence rule. See `src/lib/resolve-language.ts` for the reference pattern. Issues #2184/#2185.

## Lessons Learned

- **Collection tagging by author-surname regex causes person-collisions (2026-07-13):** Building the `stoicism` / `moral-philosophy` collections with `author:/Surname/i` rules mis-tagged books by *different people* sharing the surname substring: three distinct Lipsiuses (Justus the Neostoic vs David the physician vs Richard Adelbert the apocrypha editor), `/Vair/`→Leonardo Vairo (demonologist) not Guillaume du Vair, Francis vs Roger Bacon, Marcus Aurelius vs Augustine/Macrobius/Cassiodorus, and pure substring accidents (`/Kant/`→Nilakantha/Neelakantha, `/Hume/`→Rhumelius). ~2% of tagged books were wrong, all from **author-only rules on short/common surnames** (title-scoped rules held). **Rule:** tag collections by canonical `books.author_id` (the authors thesaurus, `authors._id`), not by regex on the `author` string; when regex is unavoidable, pair a short/common surname with a title/work filter and preview collisions BEFORE tagging. Guard tool: `scripts/maintenance/audit-collection-author-collisions.mjs` — `--rule '<regex>'` lists every distinct author string a surname matches; `--collection <slug>` audits members by resolved `author_id`, flags singleton outliers + identity-unverified (null author_id) members, exits non-zero on a likely collision. See `.claude/docs/author-identity-system.md` and CLAUDE.md "Author identity".
- **Translation collapse — and how to measure it without fooling yourself (2026-06-18):** A real AI failure mode: a substantial page returns a near-empty sliver (a boundary `<note>` + the `<summary>`/`<keywords>` wrapper) instead of a translation. Tools: `scripts/maintenance/detect-translation-collapse.mjs` (corpus detector, inverse of `detect-translation-loops.mjs`), `retranslate-pages.mjs` (repair — `--model=flash` override, write-ONLY-when-healthy guard, idempotent, `page_revisions` backup), `translation-anomaly-rates.mjs` (per-model rates). `translate-worker.mjs` now self-guards (`translatePageGuarded` retries a near-empty single-page result before saving). **Rules:** (1) gate collapse on **absolute** translation-body length (<800 chars), not the body/OCR ratio alone — ratio-only flags ~50% false positives from dense pages and OCR-inflated denominators (true corpus collapse ~25k/0.59%, not the loose 51k). (2) Predicted by **page length** (median OCR 11k vs 1.7k), not content; clusters in runs; partly stochastic. Matched-by-language Latin = clean model comparison (flash 0.035% vs legacy lite 0.378%, ~11×). (3) **The worst block — Tibetan (~11,800 pages, 5.6%) — is ~87% upstream OCR repetition loops, NOT translation failure; re-translation can't fix it, needs OCR work.** (4) "Runaway/excess-length" flags were ~97% false positives (CJK expands ~3× in chars; dense Latin fills pages) — detect real loops with a repetition metric (uniqRatio), never a length ratio. Don't blind-retranslate non-Latin. PRs #2532 (tools+guard), #2541 (blog: `/blog/translation-collapse`). Related: editorial-wrapper quote leak (CLAUDE.md "Quote & snippet integrity").
- **Free-text search results are candidates, not identity matches (2026-06-04):** `scripts/upgrade-artwork-images.mjs` upgraded low-res artwork images by free-text searching Commons for `<author> <title>` and taking the highest-res hit — no check that the file depicted the same artwork. "El Greco Angelic Concert" matched a 2013 concert photo of a folk band, served as the painting for 3+ weeks; a vision audit found **233 of 520 upgrades (45%) were wrong images**. All reverted to the import-time original (`image_source.identifier`, falling back to the percent-encoded `File:` page URL in `source_url`) and CLIP re-embedded — stale embeddings outlive the image fix, so any image swap must also refresh `clip_embeddings` (delete rows → idempotent backfill re-embeds; `artwork_embeddings` is text-on-metadata, unaffected). The upgrade script now vision-verifies every candidate (fails closed). Rule: *any* pipeline that swaps a stored asset based on search/AI output must verify identity against the record before writing, and must refresh derived artifacts (embeddings, thumbnails, materialized views). Tooling: `scripts/maintenance/audit-upgraded-artwork-images.mjs` + `revert-bad-artwork-upgrades.mjs`. PR #2427.
- **Translation tag sanitization (2026-03-15):** Sanitizer fixes unclosed/malformed XML tags in translations. Backfilled.
- **Cover selection algorithm (2026-03-19):** Covers now picked by `detected_images.gallery_quality` score, not just `page_type`. 810 books backfilled.
- **Semantic alignment scoring (2026-03-23):** Embedding-based OCR↔translation quality measurement. Per-page cosine similarity, flag threshold 0.82. Issue #340.
- **Never store `/api/image?url=` as `book.thumbnail` (2026-03-10):** Crashes SSR. Store direct http(s) URLs only.
- **Import language precedence: source beats caller (2026-05-30):** All six import routes set `language` from caller input first, ignoring the source's own metadata — so a caller's "Latin" (the *work* language) overrode IA's `metadata.language:rus` (the scanned *manifestation* = a Russian translation). `language` conflated work-vs-manifestation (FRBR). Fix: `resolveLanguage()` (`src/lib/resolve-language.ts`) lets empirical source signals win the manifestation language; caller becomes `original_language`; conflicts set `language_review`. PR #2198 (boundary) + #2211 (backfilled 11,135 records). Issues #2184/#2185.
- **Don't auto-flip catalogued language from page-OCR (2026-05-30):** page `<lang>` tags have false positives — facsimiles & critical text-editions OCR their Latin/English *apparatus* not the original (Book of Kells, Codex Alexandrinus, Septuagint), and Devanagari serves both Sanskrit and Hindi so Gemini mis-tags Sanskrit as Hindi. The audit (`scripts/maintenance/audit-language-provenance.mjs`, whole-book sampling) + `backfill-language-provenance.mjs` flag candidates; display flips need human triage (`--flip-display` is opt-in). Of 93 flagged, only 32 were confidently corrected; 61 held.

- **Artwork enrichment silently destroyed the source `description` (2026-06-02):** `scripts/artwork-enrichment.mjs` promotes Gemini-vision output to top-level book fields (`display_title`, `author`, `description`, `resource_type`, `summary`). It recorded `field_provenance.previous_value` for display_title/author/resource_type, but the **`description` overwrite kept no previous_value** — so the original imported catalog text (e.g. ContentDM "Hashika-e = measles posters no. 8 of 49") was overwritten and unrecoverable from Mongo. Fixed: it now writes `field_provenance.description.previous_value` **and** snapshots the original to `image_source.source_description`. Rule: *any* enrichment promoting AI output to a source-of-record field must preserve the prior value with provenance — audit every overwrite, not just the obvious ones.
  - **Importers must snapshot raw source metadata at ingest.** Artwork importers should write the source catalog block (title/description/dates/rights) into a durable field (`image_source.source_description` / `catalog_metadata`) at import time, so later enrichment can never destroy the source of record. The hashika-e importer (`scripts/import/import-hashika-e-posters.mjs`) and `import-umn-health-texts.mjs` store `image_source.iiif_manifest` + `source_url`, which is the durable re-derivation path.
  - **Remediation for already-enriched artworks: re-import from IIIF.** Artworks enriched before this fix have lost their original imported `description` in Mongo. The durable source of truth is the IIIF manifest (`image_source.iiif_manifest` / `source_url`) — re-fetch it and restore original catalog metadata (title, description, dates) into `image_source.source_description` (+ provenance) for the back-catalog of `content_type:'artwork'` docs.
