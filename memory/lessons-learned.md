# Lessons Learned

Cross-cutting patterns and postmortems. Domain-specific lessons go in their respective files (`pipeline-ops.md`, `data-quality.md`, `ui-navigation.md`).

## General Patterns

- **Cloudflare does not honour `Vary`, so RSC payloads poison page cache (2026-08-24, UNRESOLVED):** A plain browser navigation to `/book/history-of-both-worlds-macrocosm-fludd` returned `content-type: text/x-component` from cache with `age: 53206` — nearly 15 hours of every visitor seeing a raw React Server Component payload as text. The origin sends `vary: rsc, next-router-state-tree, …` correctly; Cloudflare only varies on `Accept-Encoding`, so whichever variant populates the cache first is served to everyone for up to `s-maxage=86400`. A prefetch landing before a real navigation poisons the URL for a day. Purging the URL fixes that one page; the cause is live and will recur on any page. **Fix needed:** a Cache Rule that bypasses cache (or varies the cache key) when the `RSC` header is present. Zone-level change, so it needs whoever owns the Cloudflare zone.
- **Always verify cloud state, not just git (2026-03-22):** Lambda function names, IAM policies, and SQS queues may differ from what's in the codebase. Always check AWS console/CLI before asserting.
- **Supabase `ilike` needs trigram indexes (2026-03-25):** Queries on 1.6M rows silently timeout without `pg_trgm` GIN index. Indexed: `ustc_editions.author_1`. Needs indexing: `ustc_enrichments.english_title`, `ustc_enrichments.original_author`.
- **Prompt versioning (2026-03-14):** NEVER edit old prompt versions in DB. Create new version + move `is_default`. DB `prompts` collection is source of truth, not hardcoded `defaults.ts`. Issue #333.
- **Atlas query performance (2026-03-18):** Books collection aggregation queries take 30-80s on M40. Never compute inline in API routes. Use pre-computed snapshots in `system_config`.
- **Tenant scoping must include all follow-up queries (2026-04-17):** Adding `tenantId` at request entry is not enough. Any subsequent `findOne`, `updateOne`, `countDocuments`, `$lookup`, and helper-built query (e.g. `buildQuery`) must include `tenantId`, including fire-and-forget updates and analytics rollups.
- **Guard `after()` + honor non-stream mode in route tests (2026-04-21):** `after()` throws outside request scope (e.g., direct Vitest handler calls). Wrap it in a fallback path and keep `stream: false` JSON responses available for integration tests and non-SSE clients. See `src/app/api/embassy/chat/route.ts`.
- **Tenant admin auth must resolve role server-side (2026-04-21):** Server guards cannot rely on client `update()` token enrichment (`TenantSessionUpdater`). In `requireRole`/`withAuth`, resolve effective role from `memberships` using `x-tenant-id` + email before denying.
- **Avoid unbounded `distinct` on large tenant backfills (2026-04-27):** `pages.distinct('id', { book_id: { $in: [...] } })` can hit Mongo's 16MB distinct cap on large tenants (e.g., BPH). Always chunk by `book_id` and then chunk `page_id` for downstream `gallery_images` updates.
- **Keep the search, not just the conclusion — evidence-first beats conclusion-first (2026-06-29):** The FT system stored the *answer* (`is_first_translation` boolean) and threw away the *search* behind it, so every claim was unfalsifiable and every pass started cold. The fix is to make producers append their search to a durable ledger (`first_translation_attempts`), read it before spending, and *derive* the verdict from the accumulated pile (#2865/#2866/#2868/#2871). A "first translation" is an absence claim — only ever as strong as the documented search; the search record *is* the claim's strength. Applies to any "we couldn't find X" assertion.
- **Spot-check a derivation against PRODUCTION data before trusting unit tests (2026-06-29):** The verdict-derivation passed 10 unit tests on clean synthetic data but was wrong on the real, legacy-backfilled ledger — it false-demoted famous Chinese firsts (scholarly *studies* like Needham's *Science and Civilisation* were recorded as "prior translations" with a URL; a URL proves a URL exists, not a translation) and false-promoted books an agent had marked `not_applicable` (collapsed into "absence"). A 7-book hand spot-check caught both; hardening dropped would-demotes 328→1. Lesson: synthetic tests prove the logic; only real-data spot-checks expose how dirty the inputs are. (This is the #2876 eval-harness motivation.)
- **Gemini proposes, Claude disposes — never settle a public claim on one model family (2026-06-29):** Gemini flash-lite (Google-Search-grounded, cheap, ~63% fabrication on "a prior exists") is a *proposer*; an independent Claude Sonnet subagent (agentic WebSearch/WebFetch, adversarial refute-framing, ~57k tokens/book) is the *disposer*. Different families → uncorrelated blind spots, so a prior one fabricates the other catches (a Tier-2 test literally caught a confabulated "London 1692" prior). Don't downgrade the disposer to a small model (Haiku/flash) — that reintroduces the fabrication risk it exists to eliminate. Same-family resampling cuts variance, not bias.
- **A grounded-LLM verdict is NOT a reproducible audit trail (2026-06-27):** ~94% of live First-Translation badges (in a 400 sample; corpus-wide only **14** of ~5,800 have a real trail) have no documented search trail — but this is an architecture property, not a logging regression. The bulk FT verifier (`scripts/enrichment/discover-prior-translations.mjs`) used Gemini 3.1 Flash Lite + **Google Search grounding**, which returns the answer + `groundingChunks` (cited source URLs) but **never the literal search queries it issued** — grounding is a black box, so there was no query log to capture. The prompt also asked only for `{translations[], found_complete_prior_translation, reasoning}` (a verdict + 1-line rationale), and the apply path's `$set` even dropped `reasoning`/`groundingUrls`, persisting only `disposition` + found priors + `tools_called` into `books.translation_verification`. The #2802 backfill faithfully migrated those into `first_translation_attempts` with a self-documenting `queries: [], // legacy did not store queries` → 18,010 conclusion-only `method:'gemini_verifier'` rows. The ONLY path that captures real queries+sources is the **ft-verify skill** (`method:'claude_subagent_verify'`, independent subagents that report their own queries) — that's why it's the gold standard. **Rule:** if you need reproducible FT evidence, use the subagent path or log the queries an agent issues itself; grounding will never give it to you. **Corollary (ties to [[lesson_derive_from_unverified_source]]):** a `result:'found'` verdict is NOT grounds to demote a badge — of 2,293 live badges with a found-prior verdict, **2,112 are `weak`** strength (the tier that already caused false demotions) and only **124 `strong`** — and 0 of the strong have a reproducible trail, so even those need ft-verify before any demotion. The 3-tier evidence UI (#2801) now states each badge's tier honestly.
- **Never leave substantial edits unstaged in the shared main dir (2026-06-01):** ~10 parallel sessions share the main working dir. Any sibling's `git restore` / `git checkout --` / auto-stash-on-pull silently wipes another session's *unstaged* working-tree edits, and an unstaged discard leaves **no git trace** — unrecoverable. Lost a ~+102/−317 in-progress doc rewrite this way (#2332 Task 6). Rule: do edit work in a worktree (`EnterWorktree`) and commit early. Recovery checklist when working-tree work vanishes: `git stash list`, `git reflog`, `git fsck --no-reflogs | grep "dangling blob"` (then `git cat-file -p <blob>` to grep for distinctive content) — but if it was `git restore`, it's gone. Reinforces the Multi-Session Awareness CRITICAL section in CLAUDE.md.

- **A healthy merge rate hides a stale tail — measure the tail, not the throughput (2026-07-28):** The repo merged 300 PRs in 30 days (excellent) while 18 PRs sat >20 days untouched, including a mergeable-clean security dependency bump (#2946) open 25 days against 3 criticals in production deps. Nobody was ignoring it; it had fallen out of every session's context, because the session that opens a PR ends before it merges — the identical structural cause as worktree accumulation. Aggregate throughput is the wrong instrument: it is dominated by the fast path and is *numerically healthiest* when a long tail is being ignored. Ask per-item questions (`/reap-prs`, `/reap-worktrees`), never a global rate. Corollary for any queue: the metric that looks best is the one that averages over the thing you're failing at.
- **Green checks measure whether a PR CAN merge, never whether it SHOULD (2026-07-28):** Batch-merging eight PRs off "mergeable + test/DCO green" was safe only because each diff was read first. The ninth (#2956) classified identically and contained an unvalidated `bookId` interpolated straight into an R2 object key — the #3362 footgun, in a new authenticated write path, 25 days green. CI proves the tests that exist still pass; it cannot prove a 30-day-old design is still correct after main has moved 500 commits underneath it. Read the diff, every time, however clean the badge.
- **On a self-authored repo, a review comment is not a durable signal — use the `blocked` label (2026-07-28):** GitHub refuses `--request-changes` on your own PR, so `reviewDecision` stays null no matter how serious the finding. A comment scrolls out of view and the next session sees a green, mergeable PR with no indication anyone objected. The label survives; `/reap-prs` classifies on it. Generalizes: when a platform's intended mechanism is unavailable to you, find the signal that persists across sessions rather than assuming the comment was enough.

- **A missing `imagecount` is not a missing book — count the IIIF canvases (2026-09-07):** IA items whose page images ship inside a `Single Page Processed JP2 ZIP` or DjVu container report **no** `imagecount`, and any fallback that counts `.jp2` entries in the file list sees the container as one page. Four pre-1930 acquisitions were nearly dropped as "PDF-only" on that reading, and al-Maqrizi's *Khitat* (MIFAO 30/33) actually **was** dropped a session earlier for exactly this — it has 207 and 127 canvases. Ask `https://iiif.archive.org/iiif/3/<id>/manifest.json` and count `items[]`. `/api/import/ia` already gets this right (manual → IIIF → `imagecount` → loose `.jp2`); the ~12 ad-hoc scripts reading `imagecount` directly do not, and the worked example at `src/lib/api-client/images.ts:222` teaches the wrong pattern. **This wants a shared helper, not a doc line.**
- **A probe that cannot fire returns the same answer as a probe that found nothing (2026-09-07):** Five nulls in one session were artifacts rather than findings — `\b` double-escaped through a shell into a Mongo `$regex` (0 hits); `curl` not following a 302, read as "IA has no larger derivative"; `/api/search` silently falling back to a default lane and returning **identical** results for "Harkhuf" and "Herkhuf"; and IA's OCR emitting Latin-letter noise for Arabic script, so `ia_ocr_detected` reports "Latin" and outranks the cataloguer (#4582). A positive control — the same probe against something known present — caught three of the five. Run it before trusting a null, **including a convenient null that agrees with what you already believed**; two of these did.
- **`pages_search` is READY, and `$regex` cannot see it (2026-09-07):** A page-text scan written as `find({'ocr.data': {$regex: …, $options: 'i'}})` collscans ~20M documents. The Atlas Search index is Lucene, `dynamic: false`, mapping `translation`/`ocr`/`book_id`/`id`/`page_number`, and is reachable **only** through the `$search` aggregation stage. No b-tree index can substitute: those fields are multi-KB and blow the ~1024-byte index key limit, and a case-insensitive unanchored alternation could not prefix-scan even if they fit. `db-health.mjs` calls the regex path a "fallback" for when the index is *absent* — when it is present, use `$search` (`src/lib/atlas-search.ts`).

## Incident History

- **Atlas outage from search index build (2026-03-10):** Building Atlas Search index on 1.84M pages collection caused full database outage. Post-mortem: #144.
- **Batch OCR RECITATION failures (2026-03-20):** Gemini Batch API refused books with copyrighted content markers. Fix: added content-type filtering in collector. 2,005 failed books reset.
- **Gemini File API quota exhaustion (2026-03-20):** 20GB quota filled by uncleaned JSONL files from batch jobs. KEY_2 permanently broken. Fix: auto-cleanup in orchestrator + collector, switched to TIER3 key.

## Meta

- **Don't retry dead services (global rule):** If an external service fails twice with same error, stop and pivot. Archive fallback chain: Internet Archive → Gallica → HathiTrust → Project Gutenberg.
- **Concurrency kills Atlas (global rule):** >40 concurrent Lambda jobs saturates Atlas. Monitor via adaptive limits dashboard.
