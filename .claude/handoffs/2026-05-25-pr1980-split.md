# 2026-05-25 — PR #1980 split into cleanup (#1986) and opt-in tooling (#1988)

A contributor opened PR #1980 ("Cleanup codebase and adding code-review graph to reduce token consumption") that bundled two unrelated concerns: dead-code removal (uncontroversial) and forced adoption of a third-party MCP server (risky). The combined PR would have shipped a real production bug and a meaningful supply-chain footgun. Split, reviewed, and merged in two pieces.

## What the PR proposed

- **439 additions / 17,899 deletions** across 34 files
- Deleted 16K-line `lamejs-bundle.js` (regenerated by a new `prebuild` script — fine)
- Deleted ~15 "orphan" components (mostly fine, one real bug)
- Added `code-review-graph` MCP server adoption: a `PostToolUse` hook running `code-review-graph update --skip-flows` on every Edit/Write/Bash, plus six near-identical doctrine files (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.cursorrules`, `.windsurfrules`, `.kiro/steering/`) instructing agents to ALWAYS use the graph before Grep/Glob/Read
- Removed the existing multi-session branch-safety `PreToolUse` hook from `.claude/settings.json`

## What went wrong

Two real issues, caught in review before merge:

1. **`InputWidget.tsx` was tagged as dead and deleted, but it was still in use.** `src/app/founding-donors/page.tsx:3` imported it and rendered it at line 337. Merging would have broken the `/founding-donors` route at build time. The author appears to have used `code-review-graph`'s "find dead code" feature to identify orphans, but the graph's view was either stale or missed the import. This is the canonical "stale static analysis hallucinates dead code" failure mode.

2. **`@types/archiver` and `@types/three` were removed.** The author assumed the runtime packages ship their own types at the versions we use. They don't. CI caught this with type errors in `src/app/api/[tenant]/books/[id]/download/route.ts`, `kdp/bundle/[id]/route.ts`, `books/[id]/download/route.ts`, and both research constellation viz components. `@types/d3` removal was OK (only `d3-hierarchy` is imported and it ships types).

Both bugs would have been caught by a normal `npx tsc --noEmit` before opening the PR.

## Why static graphs miss things on this repo

The repo has structural patterns that Tree-sitter-based analysis can't model:

- **Tenant subdomain routing** — `src/proxy.ts` rewrites paths by host. `bph.sourcelibrary.org/book/X` and `sourcelibrary.org/embed/bph/book/X` are the same page, served via host-aware rewrite, not import graph.
- **Atlas/Supabase collection scoping** — `getDb().collection('books').find({ tenantId })` — the graph sees a generic Mongo query, not the cross-tenant leak risk if `tenantId` is missing.
- **Dynamic requires** — `src/lib/embassy/podcast.ts` does `require('../vendor/lamejs-bundle')`. Tree-sitter doesn't link computed-path requires.
- **Cron triggers, Lambda handlers, worker scripts** — the trigger lives outside the import graph. A function called only by a Vercel Cron looks orphaned to the graph.

These are exactly the areas where a wrong "no callers" answer is most dangerous (tenant leaks, broken cron jobs, deleted live code). The doc calls each one out by name.
