# Artwork Enrichment — Open Questions

These need to be resolved before building the Gemini Vision enrichment pipeline.

## Taxonomy / Facets

The book facets (tradition, domain, form, sphere, era, mode) don't map to visual art:
- **Form** (treatise, commentary, letter, poem...) — meaningless for paintings
- **Sphere** (natural philosophy, medicine, theology...) — partially applicable
- **Mode** (theoretical, practical, devotional...) — doesn't fit

Options:
1. **Separate facets for art** — e.g., medium, subject, movement, period, technique, iconographic tradition
2. **Shared facets where they overlap** — tradition (Neoplatonism, Hermetica) and era work for both; add art-specific ones
3. **Don't facet art at all** — just use free-form tags + Wikidata structured data (genre, movement, depicts)
4. **Let Wikidata BE the taxonomy** — P135 (movement), P136 (genre), P180 (depicts) are already structured. No need to reinvent

Leaning toward option 4: Wikidata provides better structured classification than anything we'd build. The faceted tags add value for books because books don't have Wikidata structured data. Art does.

## Descriptions — What do we actually want?

Current Commons descriptions are mostly useless ("Print; Prints" or catalog-speak). AI descriptions could add real value, but what kind?

**Options for description style:**
- **Art-historical** — formal, like a museum wall label. "This engraving depicts..."
- **Philosophical/contextual** — connects the image to the intellectual tradition. "In Ficino's framework, this image represents..."
- **Technical** — about the craft. "Goltzius achieves remarkable tonal range through..."
- **Narrative** — tells the story. "The scene shows..."

The prototype descriptions (Birth of Venus, Melencolia I) were philosophical/contextual — connecting to Ficino, Agrippa, etc. Those were written by hand and they're good. Can Gemini do that at scale?

**Risk:** Generic art-historical descriptions are AI slop. "This masterful work by the renowned artist..." — adds nothing.

**What might actually be valuable:**
- One sentence: what is depicted (for people who don't recognize it)
- One sentence: who made it and when
- One sentence: why it matters to the Source Library tradition (the cross-reference)
- That's it. Three sentences. Not a museum essay.

## Iconographic Elements — Worth automating?

The hand-written ones (Birth of Venus: "Venus on shell → soul's descent into matter") are great because they connect visual elements to philosophical concepts.

Can Gemini do this? It could identify visual elements (figures, objects, symbols) but the philosophical interpretation requires knowledge of the specific Neoplatonic/Hermetic tradition. This might be better as:
- **Gemini identifies** what's in the image (visual inventory)
- **Cross-references** are generated by matching those elements to existing Source Library texts
- **Philosophical interpretation** is human-curated for key works, absent for the rest

## Cross-References — The actual hard problem

How to automatically link artworks to Source Library books?

**Easy matches:**
- Same author (Fludd's books ↔ Fludd's diagrams)
- Same subject (Hermes Trismegistus depictions ↔ Corpus Hermeticum)
- Same artist's intellectual circle (Botticelli ↔ Ficino)

**Hard matches:**
- Iconographic connections (Melencolia I ↔ Agrippa's De Occulta Philosophia — requires knowing the intellectual history)
- Thematic connections (Teniers' alchemist paintings ↔ practical alchemy texts)

This might be where Gemini adds the most value — not generating descriptions but generating cross-reference suggestions that a human can confirm.

## What to do now

1. **Get Wikidata IDs** — this is purely mechanical and high-value
2. **Don't do Gemini enrichment yet** — wait until the taxonomy and description format are decided
3. **Hand-curate cross-references for 20-30 key works** — this defines the pattern that automation should match
4. **Test Gemini on 10 artworks** — see what it produces before committing to a pipeline
