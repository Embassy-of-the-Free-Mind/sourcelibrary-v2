# Author identity — the `authors` thesaurus

**Read this when:** Reading or writing `books.author`, `books.author_id`, the `authors` collection, or `/author/[slug]`.

*Split out of `CLAUDE.md` on 2026-08-04. The text is unchanged apart from cross-references repointed to their new files. See `.claude/docs/knowledge-layer.md` for why this tier exists.*

---

"Who wrote this, and is *this* Andreas the same as *that* Andreas?" is answered by the canonical **`authors`** collection — one doc per person, `_id` = canonical slug, with `variants[]` / `variant_slugs[]` / `viaf_id` / `wikidata_id`. It **supersedes** the legacy `entities` layer. Umbrella issue #2179.

- **Read `books.author_id` → `authors._id`, not `author_entity_id`.** `author_id` is the canonical FK (~74% of live books linked); `author_entity_id` → `entities` is transitional and being retired. Both are written during migration.
- **Don't render `authors.book_count`** — it's a stale build snapshot. The true count is the read-path union query.
- **Build/enrich scripts:** `scripts/maintenance/build-authors-collection.mjs` writes the collection (deterministic name-key ∪ VIAF ∪ Wikidata, #2202); `reconcile-authors-grounded.mjs` anchors the tail to Wikidata/VIAF using each author's books as evidence (#2218). The similarly-named `build-canonical-authors.mjs` is a read-only sizer that does NOT write — don't run it to rebuild.
- **Read-path** (`/author/[slug]` → `src/lib/author-thesaurus.ts`) is flag-gated by `AUTHOR_THESAURUS_READPATH` and redirects every variant slug to the canonical one. Full design, provenance, and migration status: **`.claude/docs/author-identity-system.md`**.
- **A SEARCH TERM IS NOT METADATA. Never write the query that found a record into a field of that record.** A 2026-03-14 BSB run imported 1,353 books and stamped its own search string into `books.author` — which is why values like `Albertus Secrets`, `Fludd Medicina`, `Kircher Oedipus`, `John Dee Monas` exist: they are `<surname> <work keyword>` queries, not names. It ran undetected for four months and the wrong names reached readers, `work_id` cluster keys (`local:a:heinrich-khunrath:…`) and book slugs. **The hits skew to catalogues by construction** — a full-text title search matches every bookseller/library catalogue that *lists* a copy, so those are the top results and the least likely to be spot-checked. Hence 14 catalogues and periodicals (1751–1810) attributed to Khunrath, who died in 1605, and 16 editions of the Augsburg Confession under `Confessio Fraternitatis`. Detector: `scripts/audit/author-attribution.mjs` (#3434).
- **Two layers already answer "who wrote this", and nothing reconciles them.** `books.author` is what the source catalogue said; `ai_metadata.author` is what enrichment read off the pages. Where they disagree, the page-derived answer is often the right one and has simply never been looked at: *Demonomania de gli stregoni* (1592) was catalogued `author: "Manuzio, Aldo"` — the Aldine press printed it, Jean Bodin wrote it, the title page says so, and `ai_metadata.author` had said "Jean Bodin" for ten weeks before a reader reported it. **A printer-as-author error is not cosmetic: it costs a work-graph edge**, because the book mints a singleton local `work_id` under the printer instead of joining the cluster its siblings are in (we held three other witnesses of that work on `Q10264553`). `author-attribution.mjs` cannot see this class — it hunts strings that are not *names*, and "Manuzio, Aldo" is a name, of a real anchored person who authored other books we hold. Detector: `scripts/audit/author-vs-ai-metadata.mjs` (#3894), report-only. **It partitions, and only `person_vs_person` is a queue** — placeholder-filled (the AI *supplied* a name), undecidable-script, and institutional headings are context, not defects.
- **Neither side of that comparison is an authority, and the AI side has its own batch failure mode.** Enrichment runs in batches and a batch can carry ONE answer across every book in it: twelve books enriched 2026-04-13 all returned `ai_metadata.author: "Benedictus de Spinoza"` — al-Battani's astronomy, al-Farghani's *Elementa*, Aldrovandi's *Musaeum Metallicum*, Fabricius' surgery, Clavius' *Gnomonices*. **No row looks wrong in isolation**; each is a book with a confident, specific, unrelated author, so the defect is visible only ACROSS rows. Signature: one `ai_metadata.author` asserted over books whose catalogued authors are mutually unrelated *after name-form folding* — a real author spans several spellings of themselves, not al-Battani and Aldrovandi. This is why the detector reports and never writes.
- **Comparing names by exact token overlap calls one person two people.** `Cicéron`/`Cicero`, `Aristoteles`/`Aristotle`, `Boehme, Jacob`/`Jakob Böhme`, `Claude de Saumaise`/`Claudius Salmasius`, `Ovid`/`Publius Ovidius Naso` — 92 such pairs, a quarter of the first queue, were the corpus's own historiography rather than defects. Use `scripts/lib/name-equivalence.mjs` (`sameNameForm`, unit-tested in `tests/unit/name-equivalence.test.ts`) plus a thesaurus-variant lookup, never raw string equality. Every rule in it carries a **length floor** and they are load-bearing in the other direction: at ≥5 the prefix rule is safe, below it `Ott` prefixes both Otto and Ottaviano; at ≥7 the one-edit rule is safe, below it Otto/Otho collapse. Loosening either to catch a miss starts merging real people, and a false merge deletes an attribution error from the queue silently.
- Two further traps that detector was built on: `norm()` strips non-Latin characters, so a CJK or Cyrillic name yields an empty token set and reads as guaranteed disagreement — test whether the metric *can* judge, not whether the strings differ; and a trailing `\b` after a truncated stem — `/\bbibliot\b/` — matches nothing, which is how "Biblioteca Aldina" reached the person queue.
- **The record is self-describing: `books.title` is a transcription of the title page, and early-modern title pages name their author by convention.** That is a corpus-wide, zero-cost attribution signal, and it reaches where the enrichment comparison cannot — only 12% of visible books carry an `ai_metadata.author`, which is why that audit corrected the 1590 *Aminta* to Tasso while the 1581 and 1583 editions of the same poem stayed under "Manuzio, Aldo". Detector: `scripts/audit/title-page-attribution.mjs` + `scripts/lib/title-page-attribution.mjs` (#3894 item 5), report-only, scoped to printer dynasties so the test is two positives ("catalogued author is a printer" AND "the page names someone else") rather than one loose one. **The distinction that makes it safe is grammatical: a Latin title page names the EDITOR as prominently as the author, in a different case** — `Auli Gellii Noctium Atticarum libri` is a genitive (Gellius wrote it), `P. Terentius Afer a M. Antonio Mureto emendatus` is an ablative plus participle (Muretus only corrected it). Promoting the second swaps one wrong byline for another that looks right, so editor-role captures are detected and never proposed. Two further traps: a **genitive capture is a declined form** (`Nicolai Clenardi`) and must be nominativised before it is written — the audit flags this as `needs_nominative`, 51 of 112 rows; and `SELF_NAMED` must be generous, because a miss there is a false *accusation* — a printer signs his own page in Latin (`Estienne` → `Henrici Stephani`, sharing no letters with the catalogued form, so no orthographic rule reaches it).
- **`authors.variants[]` is a MATCH SURFACE, and 11% of it cannot safely be matched on.** Every resolver in the identity layer — the read path, `backfill-author-canonical-links.mjs`, `nominativise.mjs`, `author-vs-ai-metadata.mjs` — uses variants as lookup keys, so a variant naming several people, a contributor, or an edition is not inert debris but a trapdoor onto the wrong person. It has already fired: the `cicero` doc carries `"Cicero (ed. Manutius family)"`, which is why a title page reading "Aldi Manvtii" resolved to **Cicero**. Measured 2026-08-11: **1,126 of 9,804 variants unsafe across 734 docs** (721 multi-person, 397 role-annotated), and 1,526 books carry one. **But carrying a string is not depending on it**: measured against production, **ZERO** of those books would be orphaned by de-matching, because the canonical-link backfill already gave every one an explicit `author_id`. The first cut of this audit counted books whose `author` equalled the variant and called all 1,526 load-bearing — the wrong denominator, and it inverted the conclusion. De-matching is safe today; measure `author_id`-less books, never string carriers. Detector: `scripts/audit/thesaurus-variant-shape.mjs` + `scripts/lib/variant-shape.mjs`, report-only. **The repair is to stop MATCHING on these, never to delete them**: a compound may be the only surviving record that a volume had co-authors (feed it to #2916), and removing a variant that books still carry ORPHANS them — the byline stays and the author page silently loses the book. The same walk surfaces **21 variant strings claimed by more than one author doc** — a duplicate-person signal (`roger-bacon` [Q171677] ⟷ `bacon-roger`, `zhuangzi` [Q47739] ⟷ `zhuangzi-2`), alongside **31 slug-collision pairs** (`x` and `x-2` both present, books split across both) minted when the additive script hit a slug clash instead of merging. **No two docs share a `wikidata_id`**, so the merge-by-QID discipline held; the duplicates are all in the unanchored tail. Two false-positive classes the classifier must keep matchable, both found in production: a **transliteration pair** is ONE person written twice (`"Zhang, Jiebin, 1563-1640; 張介賓, 1563-1640"` — reading it as two stripped the romanised key off 40 books), detected by presence of a non-Latin script on exactly one side *plus* agreeing life-dates, never by a Latin-share ratio (the romanised qualifier "approximately" appears on both sides); and an **institutional heading legitimately contains "&"** (`"Drametse & Ogyen Choling Collection"`).
- **Three correct guards can still leave a gap; check the gap, not each guard.** Nothing caught the above, and no single piece was wrong: `qa-author-date-anachronisms.mjs` tests only the **birth** side (this is the death side); `quarantine-non-person-authors.mjs` fixes the `authors` thesaurus and never touches `books.author`, and its interlock rightly refuses to touch anchored real people — so **Khunrath was uncatchable there**, being a genuine VIAF-anchored author of other books we hold; and `author-date-window.mjs` deliberately refuses death-side exclusion because a 1925 Boethius is a reprint (he carries 55). The usable signal only exists in the **combination**: long-dead author **AND** reference-genre containing book (`posthumousMisattributionLikely()`). Neither half alone works — a person *can* compile a catalogue (Guanzelli's *Index librorum expurgandorum*, Bernardus de Lutzemburgo's *Catalogus haereticorum*), and death-side-alone flags every reprint in the corpus.
- **`authors` carries no life dates** — 0 of 4,825 have a birth/death year, only `birth_place`/`death_place`. Death years come from `entities.wikidata_death_date` via `authors.entity_ids`, and only 1,229 of 3,253 entity-linked docs resolve one, so any date-based author check abstains on ~⅔ of the corpus. Don't read a clean result from one as coverage.
- **`is_person: false` is a READ-PATH gate, and the read path is `classifyNonPersonAuthor` (`src/lib/non-person-author.ts`).** `quarantine-non-person-authors.mjs` set the flag on 59 docs and **nothing in `src/` read it for a year**, so every quarantined heading rendered with a portrait slot, life dates, an "Artist page" link and a schema.org **`Person`** node — telling search engines that `Theatrum Chemicum`, `British Museum` and `Anonymous` are human beings (#3483). The flag is **absent on 4,766 of 4,825 docs**, so consumers must test `=== false`; a truthiness check strips the person framing from every author on the site. A `merged_into` tombstone is not a non-person — the resolver follows it to its primary first. Institutions render as `Organization`; work titles and placeholders get **no entity node at all** and a `CollectionPage`, because there is no entity to point at. Don't "simplify" that to one non-person branch: a museum really does author its own catalogue, and a book title never authors anything.
- **Quarantining a doc does not clear the byline, and clearing the byline retires the page.** The two layers are independent: `authors.is_person` governs *rendering*, `books.author` governs *existence* — an author page exists only while books point at it, so clearing a bogus `books.author` 404s the page with no code change. Decide which layer a given heading belongs to before writing anything. Roughly half of the 59 were the #3434 data defect (fix the books; the page retires itself) and half were legitimate corporate or anonymous headings (keep the books; drop the person framing).
- **Enumerate author defects by the author STRING, never by the thesaurus doc.** A doc-keyed sweep walks `author_id` ∪ `author_entity_id` ∪ `variants` and silently misses any book whose string never joined — that gap hid `Kircher Oedipus` (6 periodicals), `Kircher Musurgia`, `Kircher Mundus` and `AnonymousUnknown author` from a sweep that believed it was exhaustive, and `scripts/audit/author-attribution.mjs` (which scans strings) found all of them afterwards. Corollary for repairs: **key the fix on whatever unit was actually verified.** #3434 keyed on book ids because the *name* was valid and only the pairing was wrong; #3483 keys on the string because the string itself is never a name (`S.n` is *sine nomine*), which makes string-matching self-limiting rather than a widening heuristic.
- **A re-runnable repair must MERGE its backup, not overwrite it.** These scripts select by "still wearing the bad value", so a second run sees only the newly-found records — an overwriting backup would replace 770 restorable records with 15 and strand `--revert` for everything already fixed. Merge on id, and let the **earlier** `before` win: it is the true original.
- **The author layer was built and linked from LIVE books only, so the import backlog could never enter it (#3769, 2026-08-08).** `build-authors-collection.mjs:71` and `backfill-author-canonical-links.mjs` both scoped to `{visible:{$ne:false}, pages_count:{$gt:0}}` — but **imports land HIDDEN by invariant**, so every acquisition was born outside author identity and stayed there. 63,568 books had an author string and no `author_id`; **43,858 were excluded purely for being hidden**, and the backfill scanned 19,712 while reporting a tidy result. That capped a whole subsystem, not a report: `author_id` gates BOTH work resolvers (`resolve-work-ids-wikidata.mjs` requires it, `llm-verify-work-merges.mjs` blocks by it), so backlog books could not acquire `work_id` — exactly backwards, since `work_id` answers "do we already hold this?" and that pays off *while a book is still in the backlog*. `--include-backlog` linked 10,101 (83.7% → 74.8% missing). **Tell:** a maintenance script whose scanned count sits far below a population you measured independently — always print both. The thesaurus builder is still live-only, and cannot be fixed by deleting the filter: the backlog is exactly where junk author strings live (#3434 search-strings, #3770 `[object Object]`) and where institutional headings like `Drametse Monastery Collection` would be minted as *people*, which `is_person` then renders as schema.org `Person`. **The sanctioned path for backlog strings is ADDITIVE minting, not a rebuild** — `additive-mint-authors-3780.mjs` (2026-08-09: 1,506 docs minted from per-string classified verdicts, 84 variant appends, backfill then linked 24,236 books; missing fell to 42.0%). Its two write shapes cannot reshape existing clusters by construction. **Hazard found doing it:** matching a new string into an existing doc by `canonicalKey` over that doc's *variants* can land on a COMPOUND or conflated variant and pull in a different person — the Marbode doc's "Pictorius, Georgius" variant would have absorbed the real Georg Pictorius. Always print *which variant* caused a key hit and review every append; the script's `EXCLUDE_APPEND` list holds the reviewed false collisions.
- **`is_person` types the ENTITY; nothing typed the EDGE — and every attribution error of 2026-08-18 lived on the edge.** "Is this heading a human?" and "what did it do to this book?" are independent axes. An institution can be a genuine author (the Council of Trent wrote its own canons; the Yuan Office of Agriculture 司農司 compiled 農桑輯要), and a person can be a non-author (an editor, a printer, a dedicatee). Because only the node was typed, **four separate emitters asserted authorship from the raw `books.author` string** — schema.org `author` as `Person`, `citation_author` (Google Scholar), og `article:author`, and `DC.creator` — plus `creator` on every gallery image. That told search engines a Bhutanese monastery is a human being who wrote the Tantra collection, across **1,538 visible books and 4,586 gallery images**; #3483 is the same defect one layer up, on the author page. `src/lib/corporate-bylines.ts` now names four relations (corporate-author · issuer · holder · collective) behind one predicate, `bylineClaimsAuthorship()`, which every emitter must consult — **fixing one emitter and declaring victory is how this stayed live**, and only verifying the rendered page caught the other three. Where the body did not write the book, leave the authorship slot EMPTY rather than hedged: `citation_author` and `article:author` cannot express "held by", and a wrong claim is worse than a missing one. Dublin Core can, so it uses `DCTERMS.provenance` / `DC.publisher`. **Do not "fix" a wrong institutional byline by clearing it** — a byline is how a reader REACHES a book, and for the ~446 Bhutanese manuscript volumes the monastery is the only record of which collection they are from (`contributing_library` names the British Library, the *digitiser*). Blanking them is more truthful and strictly worse.
- **A pattern is a NET, never a VERDICT, when the question needs world knowledge.** Classifying 1,632 unlinked author strings by regex cut the reading list to 47 — genuinely useful — and got **2 of those 47 wrong, both calling a person an institution**: `Temple Stanyan` (the English historian of *The Grecian History*, 1774) and `One of the Old School (Gravener Henson, attrib.)`, matched on "Temple" and "School". No pattern separates `Temple Stanyan` from `Thadrak Temple`. This is the same result the title-page work measured twice more: the regex attribution pass was a **negative result** (fires on ~5%, captures offices and dedicatees), and on the Aldine set it proposed "Porta del gran Turco" — the Sublime Porte, a *place* — and "Eschine contra di Tesifonte", an oration's *title*, as authors. Use patterns to bucket; use a reader (model or human) to decide; pin the false positives as tests so the pattern cannot reclaim them. Corollary for reporting: **a bucket count is not a finding.** "451 books are institutions" was the net's output quoted as a verdict, and the true institutional figure was 1,538 because that filter had silently dropped every already-linked byline — the same subset-as-population error twice in one session.
