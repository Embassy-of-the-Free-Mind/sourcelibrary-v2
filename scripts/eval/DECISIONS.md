# OCR and translation decisions — the ledger

PRIOR ART: `scripts/eval/EXPERIMENTS.md` — the append-only RUN log (what was measured, newest first); `results/benchmark/decisions/*.json` — machine-readable rule outputs per run. Neither says what we currently DO per stratum, who decided, or when to re-measure. This file does. Design: `.claude/docs/eval-design.md` §10.

**How to read a row.** One row per stratum × question. *Evidence* names the cell (result file or store cell id), its `measure` (only `accuracy` is quality), and the grade in referenced books (exploratory < 30, directional ≥ 30, decision ≥ 50). *Rule output* is what the preregistered rule said. *Decision* is a human's — Derek's comment or merge — with its date; "rule output" alone is not a decision. *Applied in* is the PR that changed routing, a lane or a withholding rule; empty means production is unchanged. *Re-measure when* is the trigger that reopens the row.

**Is the evidence enough?** Before proposing a change, read its decision card (`.claude/docs/eval-design.md` §10.2): books per language, pooling, minimum effect, tier by dollars and reversibility, replication, judge. `node scripts/eval/decision-cards-audit.mjs` replays this month's decisions through the cards.

**How to add a row.** When a run lands (§9 landing rule), add or update the row in the same PR as the `EXPERIMENTS.md` entry. Never edit a decided row's evidence; add a new row and mark the old one `superseded by <row>`. Current routing constants: `LATIN_SCRIPT_LANGUAGES` in `scripts/lib/translate-core.mjs` (OCR: Latin-script → lite, else flash; translation: lite since #4762, except BPH and Tibetan, and — if PR #5740 merges — the #5695-measured languages). **But** `OCR_LITE_ONLY` in `scripts/lib/ocr-routing.mjs` (default ON since 2026-09-11, Derek: "OCR should only be flash-lite batch, in the meantime"; not overridden on Hetzner as of 2026-10-01) sends every new batch OCR to lite in every language, so rows below that say "on flash" describe the routing the evidence supports and pages read before 2026-09-11, not new reads.

## What the evidence says so far: levers ranked by measured effect (updated 2026-10-04)

Read this before proposing a quality change. Effects are on the 1–5 fidelity scale against published human translations (#5695, five tracks, 321 pages, two blind Opus judges, controls passed) unless marked. The rows below carry the evidence and the decisions.

1. **The transcription is the biggest lever.** Translating a transcription corrected by eye lifts fidelity +1.77 (Greek), +1.38 to +1.47 (Hebrew/Arabic/Persian), +0.70 (Latin), +0.65 (Sanskrit/Pali/Chinese). OCR is the primary cause of most low pages outside the vernaculars: Greek 16 of 22, Hebrew/Arabic/Persian 14 of 23, Sanskrit/Pali/Chinese 30%. A better translator does not repair a wrong transcription: Opus scored 1 on Greek manuscripts with invented OCR. What a real re-OCR (not a correction by eye) buys is being measured (job `reocr-lift-5700`, #5700 A5).
2. **The model is the second lever.** Flash beats Lite in all five tracks, beyond an A-vs-A floor of about 0: +0.21 to +0.53, and it cuts reversed statements (Sanskrit/Pali/Chinese 15 → 6 per 100 pages). Opus is +0.5 to +0.7 above Flash, so it is a ceiling, not a lane.
3. **Request shape is the third.** Where the source is page-exact (an open e-text), one page per request without neighbouring pages removes wrong-span pages (Tengyur 15 → 1 of 113). Where a sentence runs across a page break, folio markers place the turn about twice as accurately (Tengyur). The confirmatory A/B for the chained lane is running (#5678).
4. **Prompts and add-ons measured as noise.** v14, v16, the seam lines, v20 (OCR), a glossary (which ADDED reversals), a Sanskrit parallel, thinking, and a negation detector with a Pro fix pass (at chance out of sample). The prompt is the smallest lever: name the error class first, then pick routing, gate, re-OCR or open edition before a prompt.
5. **Typed open editions beat any OCR.** Where one exists (Tengyur/Esukhia, CBETA, Sefaria, Kanripo), use it.
6. **Instrument rules that held:** every run has an A-vs-A arm, planted controls and ties; seeds must look like real errors (a verifier caught 98% of planted errors and 27% of real ones, #5647); thinking budgets must be checked in billed tokens (flash-preview at 2048 did not think, #5695 T4).
